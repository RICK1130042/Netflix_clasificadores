# Uso de asistentes por etapa del SDLC

| Etapa | Trabajo delegado que consta | Decisión humana o límite |
|---|---|---|
| Plan | Organizar rúbrica y estructurar objetivo ([B4](B4.md)) | El usuario fijó alcance y destino main. Persona, horizonte y meta del piloto requieren validación del equipo. |
| Design | Proponer tablero y jerarquía ([B2](B2.md), [B3](B3.md)) | La fuente original de algunos prompts y del mockup no está disponible. |
| Build | Contrato, app, automatización y documentación ([B2](B2.md), [B4](B4.md)) | La regla de negocio y el uso autorizado de datos siguen sujetos a revisión humana. |
| Test | Pruebas de roles, tipos y contraste | CI comprueba reglas observables. El juicio sobre interpretación de la unidad y calidad visual sigue siendo humano. |
| Deploy | Orientación de Git y preparación de publicación ([B2](B2.md), [B4](B4.md)) | El usuario autorizó main. Canvas y credenciales se gestionan por el equipo. |
| Maintain | Proponer regeneración y auditoría del CSV | No hay observaciones de campañas reales ni monitoreo histórico aportado. |

[B1](B1.md) describe los límites del registro temprano. Los archivos distinguen prompts literales, extractos y síntesis documentales.
